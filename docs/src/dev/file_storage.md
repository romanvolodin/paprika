# Хранение загруженных файлов

Всё, что загружают пользователи, лежит в `MEDIA_ROOT`: аватарки, обложки проектов, версии, вложения чата.

В dev это `backend/media`, в продакшне — `/var/lib/paprika/media`. Пути строит один модуль: `backend/apps/core/storage.py`.

## Как устроены папки

```txt
media/
  users/
    <user_id>/
      avatar/
        <имя>-<token>.jpg
  <company_token>/
    .<название компании>                  # пустой файл-маркер
    <PROJECT>/
      <имя>-<token>.jpg                    # обложка проекта
      shots/
        <SHOT>/
          versions/
            <VERSION>-<token>/
              <VERSION>.mov
              <VERSION>.mov_converted.mp4
              <VERSION>.mov_thumb.jpg
          chat/
            <YYYY-MM-DD>/
              <имя>-<token>.<ext>
```

Пример вложения чата:
`media/k3m9x2qa/PRJ/shots/PRJ_0010/chat/2026-10-08/photo-7d2e91bc.jpg`

## Зачем столько правил?

Хочется двух вещей:

1. Чтобы человек без базы данных понимал, что где лежит. Например, когда разбирает бэкап.
2. Чтобы адрес чужого файла нельзя было угадать.

Все правила ниже — про одно из двух.

## Что попадает в путь

Только то, что не меняется: токен компании, код проекта, имя шота, имя версии, id пользователя.

Поэтому файлы никогда не переезжают. Цена за это: переносить проекты между компаниями пока нельзя.

## Папка компании

Папка компании — случайный токен (`Company.storage_token`, 8 символов `a–z0–9`). Он создаётся вместе с компанией и больше не меняется. Название компании в адресах файлов не видно.

Но человеку без БД всё равно надо понять, чья это папка. Поэтому внутри лежит пустой скрытый файл `.<название>`.

Маркер переименовывается вместе с компанией. Если записать его не удалось, это просто попадёт в лог. Источник правды — БД.

## Токены у объектов

У папки версии, вложения чата, аватарки и обложки есть свой случайный токен: 8 символов `a–z0–9`. Буквы строчные, чтобы не было коллизий на файловых системах без учёта регистра.

Токен нужен потому, что `/media/` отдаётся Caddy без авторизации. Именно токен не даёт угадать адрес чужого файла. Токен компании секретом не является.

У аватарки и обложки токен делает ещё одно дело. При замене картинки адрес меняется, и браузер не покажет старую из кеша.

Имя загруженного файла у аватарки, обложки и вложения чата сохраняется. Токен добавляется перед расширением: `Постер.PNG` → `Постер-k3m9x2qa.PNG`. Расширение остаётся в том регистре, в каком его загрузили.

## Очистка имён

Перед попаданием в путь имя очищается:

- остаются буквы (в том числе кириллица), цифры, `.`, `_`, `-`;
- всё остальное заменяется на `_`;
- ведущие точки убираются;
- длина ограничивается.

Разные имена могут дать одну папку (`A B` и `A_B`). Это допустимо: файлы внутри различаются токенами и ничего не перезапишут.

## Производные файлы

Производные файлы лежат рядом с исходником, в папке версии. Их имя — полное имя исходника с суффиксом: `PRJ_0010_v01.mov_converted.mp4`, `PRJ_0010_v01.mov_thumb.jpg`. Сразу видно, из чего посчитано.

## Вложения чата

Вложения чата лежат в папке с датой загрузки по UTC. Точное исходное имя хранится в БД (`Attachment.filename`).

## Удаление

Файлы удаляются по одному: сигналами `post_delete`, после коммита транзакции. Потом убираются опустевшие папки.

Папка целиком не удаляется, поэтому склеенные папки безопасны (см. «Очистка имён»). Папка компании остаётся, пока в ней лежит маркер.

## Длина полей

Поля файлов версий и вложений чата имеют `max_length=512`. У аватарки и обложки — 255.

## Что осознанно не сделано

- **Адреса файлов не защищены авторизацией.** Утёкшая ссылка открывает файл. Если понадобится, `/media/` можно отдавать через Django (проверка доступа) и Caddy. На диске при этом ничего не меняется.
- **Нельзя переносить проект в другую компанию и переименовывать шот, версию или код проекта.** Путь к файлам зависит от этих имён.
- **Заголовки в Caddy.** Для `/media/` добавлены `Referrer-Policy: no-referrer` и `X-Robots-Tag: noindex`. `nosniff` стоит для всего сайта. Листинг папок выключен.
