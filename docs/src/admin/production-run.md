# Запуск Паприки

Эта инструкция для администратора, который ставит Паприку на боевой сервер (VPS).

Весь внешний трафик идёт через один контейнер — **Caddy**. Он сам получает HTTPS-сертификат (через Let's Encrypt), отдаёт собранный фронтенд и документацию и передаёт запросы бэкенду.

## Что нужно заранее

- VPS с Docker, Docker Compose и утилитой `just`. Сервер ещё не готов? Смотрите [настройку VPS](vps-setup.md).
- Домен (например, `paprika.example.com`), у которого A-запись уже указывает на IP сервера.
- Открытые на сервере порты **80** и **443**.

Про DNS стоит сказать отдельно. Без рабочего DNS Caddy не получит сертификат. Хуже того: если DNS ещё не готов, а вы уже несколько раз перезапустили стек, Let's Encrypt может временно забанить вас за повторные неудачные попытки.

## Первый запуск

Клонируем репозиторий и переходим в папку проекта:

```bash
git clone https://github.com/romanvolodin/paprika_v2.git
cd paprika_v2
```

Дальше все команды выполняем в корне репозитория.

```bash
just init prod ваш-домен.example.com
```

`just init prod` задаёт один вопрос: email для уведомлений Let's Encrypt о продлении сертификата. Всё остальное команда делает сама:

- генерирует случайные `PAPRIKA_SECRET_KEY` и пароль базы данных;
- вписывает домен в `backend/.env`;
- создаёт файл `.paprika-mode`. По нему остальные команды `just` понимают, что перед ними продакшн, а не dev-машина.

После этого команда просит:

1. убедиться, что домен действительно указывает на этот сервер (DNS);
2. выполнить `just run`, а затем `just superuser`.

```bash
just run          # соберёт образы и поднимет весь стек в фоне
just superuser     # спросит email, пароль, имя и фамилию - создаст первого администратора
```

Миграции и сборку статики Django-админки делать руками не нужно: `just run` выполняет их сам при каждом старте `backend`.

Откройте `https://ваш-домен` в браузере. Сертификат Caddy получит сам при первом обращении. Это может занять несколько секунд.
